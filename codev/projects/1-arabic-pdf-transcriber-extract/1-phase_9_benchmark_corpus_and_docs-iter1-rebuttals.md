## Issues addressed

### 1. Corpus incomplete vs phase-9 plan (codex + claude)

> Plan required `digital-clean >= 3`, `digital-broken >= 2`, `image-scan >= 3`, `mixed >= 1`, plus edge fixtures. Repo had `digital-clean (3)`, `digital-broken (2)`, `image-scan (1)`, `mixed (0)`, `edge (0)`.

**Fixed.** `tools/generate_fixtures.py` extended with new generators:

- `image-scan/scan-ar-2col.pdf`, `image-scan/scan-ar-headings.pdf` — bring `image-scan/` to 3 fixtures.
- `mixed/native-then-scan.pdf` — 2-page PDF where page 1 has a native text layer and page 2 is image-only. Exercises the per-page gating contract (one PDF, two branches).
- `edge/empty.pdf` — single-page no-text-layer fixture (spec scenario 11).
- `edge/truncated.pdf` — reportlab-generated PDF then byte-truncated to wipe the xref table; triggers `CorruptedPDFError` at open time (spec scenario 13).
- `edge/a2-poster.pdf` — A2 page size (1190×1684pt) for memory-ceiling sanity (spec scenario 17).
- `edge/intra-region-bidi.pdf` — paragraph mixing Arabic-style content + Latin proper nouns (spec scenario 16).

`tests/fixtures/pdfs/LICENSES.md` updated with provenance + license for every new fixture.

### 2. ASCII-only "digital-clean" fixtures don't satisfy "Arabic benchmark" (codex)

**Acknowledged + scoped to follow-up.**

The phase-2 fixtures are explicitly **geometry-and-Unicode-plumbing** fixtures, not realism fixtures, per the LICENSES.md note that landed in phase 2. The lone Arabic-content fixture (`lorem-ar-real.pdf`) carries real Arabic codepoints in the text layer. A realism-focused Arabic benchmark needs proper provenance (InDesign / LaTeX-bidi / Wikisource scans with documented licenses) which is a substantial effort outside the phase-9 scope window. The follow-up is documented in:

- `CHANGELOG.md` "Known limitations / deferred"
- `tests/fixtures/pdfs/LICENSES.md` "Scope and follow-ups"
- `README.md` Status block now explicitly says "synthetic, reproducibility-focused"

### 3. Missing ML-path CER acceptance tests (codex + claude)

**Partially fixed.** `tests/_cer.py` ships the in-tree Wagner-Fischer CER implementation; `tests/test_cer.py` covers it with 20 unit tests including the spec's `≤ 0.05` tolerance band. `tests/test_e2e.py::test_ml_path_cer_below_tolerance_real_models` is added behind `@pytest.mark.slow` as the documented entry point. The reference texts for the `image-scan` and `mixed` fixtures are the deferred follow-up (they require running the real HF models on the in-tree fixtures and curating the references; that lands with the corpus realism follow-up).

### 4. Missing `tests/test_perf_smoke.py` (codex + claude)

**Fixed.** `test_perf_smoke.py::test_native_path_under_budget` runs the native path on the largest available digital-clean fixture and asserts wall-clock under 5 s with explicit "generous slack" rationale in the docstring. Not a hard CI gate per the plan's "Implementation Details" — soft signal that fires only on order-of-magnitude regressions.

### 5. Missing exit-code tests for scenarios 11, 12, 15 (claude)

**Fixed.** Added to `test_e2e.py`:

- `test_edge_empty_pdf_exits_zero` — scenario 11.
- `test_encrypted_pdf_exits_3` — scenario 12 (patched encryption boundary).
- `test_strict_mode_aborts_on_first_failure` — scenario 15 (forced via injected validator that always raises). The CLI's catch-all `ArabicPdfTranscribeError` arm was added to map strict-mode aborts to exit 2 with a stderr message rather than letting the exception propagate.
